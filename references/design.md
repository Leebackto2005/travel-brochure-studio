# 设计与配图

严格按选定模板整理内容：保留原始形状、比例与视觉节奏，不照搬模板中的固定天数与产品事实。PPTX默认保留原SVG画布比例；行程长度变化通过同结构续页处理。下表描述原模板特点，不授权重新设计。用户授权HTML→PDF时，可使用独立分格纸张模板，参见 [HTML工作流](html-pdf.md)。

|方向|结构|字与色|图片策略|
|---|---|---|---|
|editorial 旅行编辑|大标题、主栏加窄侧栏、大数字、细分隔线|暖白、炭黑、朱橙；宋体标题配无衬线正文|横向主图+独立小图，图注不压关键主体|
|zine 旅行手记|交错图文、路线轴、宽窄图、温和不对称|奶油、森林绿、陶土橙|交错只改变方向，统一外边距与图文基线|
|swiss 瑞士信息网格|左侧编号带、严格列宽、功能信息条|白、黑、电蓝、少量黄橙|固定网格、等大主推；靠排序和比例而非圆角制造节奏|
|boutique 精品旅行|舒展双图、细线、路线节点、克制侧栏|米白、深绿、低饱和金|更大留白和较少图片，双语正文长则拆页|

蓝橙模板的时间轴和清新模板的主图+附图也作为参考。参考中的弧形或斜切只用于装饰或安全留白，不强行裁掉人脸、酒店和景点标识。不要给所有产品都用蓝黄胶囊标题。

## 先诊断视觉问题，再决定怎么改

用户提出“不够好看”“图片不好”“想优化”时，先查看实际页面和整册缩略图，指出最影响结果的2—3处具体问题，以及对应的修改办法。不能只回答“提高高级感”。根据 [需求沟通](discovery.md) 问清允许修改的范围；用户已授权的字体、配色或图片优化直接执行，只有超出选定模板结构时才再讨论。

| 看见的问题 | 优先处理 | 避免的做法 |
|---|---|---|
| 所有图一样抢眼，看不出重点 | 按卖点选主图、辅助图和细节图；固定等大图框时，用画面内容、排序和图注形成主次 | 未经要求放大某一框，或给每张图都加大标题 |
| 多张相似建筑或同角度房间，翻页单调 | 在已确认主题内组合全景、体验和细节；酒店仍保留外观/房型配对 | 为丰富画面混入不在行程内的景点或其他酒店 |
| 内容全挤在页顶，底部出现大块无意义空白 | 先看该页信息是否完整，再在允许范围内调整图高、模块间距或相邻页内容分配，保留完整正文 | 用无关照片、营销空话填空，或强迫每页填满 |
| 标题、正文和图注缺少层级 | 明确页标题、模块标题、正文、注记四种角色，同角色统一字号和字重 | 所有文字加粗，或以反复增加颜色代替层级 |
| 照片色温、饱和度、拍摄季节混乱 | 优先重选同一视觉方向且信息准确的照片；在适用图片工具中按授权调整 | 直接套强滤镜，改变食物颜色或酒店实际面貌 |
| 换主色后仍残留旧底色，边框过重 | 统一主色、强调色、纸色、文字色及浅色底；弱化表格线和辅助块 | 所有目的地都默认棕金，或每个模块都用高饱和色 |
| 图片糊、建筑顶部或床铺被裁掉 | 找更合适的原图，按图框比例筛选，再调焦点或contain | 拉伸、截图放大、去掉水印冒充原图 |

图源不足或质量不合格时，主动按 [素材库选择与候选图流程](asset-libraries.md) 推荐适合的来源，并给出对应位置、搜索词和选择理由。

## 建立小而明确的视觉约定

在原模板允许范围内确定以下内容，并用于所有同类页面，不需要另建复杂设计系统：

- **配色角色**：从已确认KV/品牌中取主色，再选少量强调色；大面积正文用清楚的纸色与文字色，金色等装饰色不承担小字阅读。不要为了与照片统一而把所有照片染成同一颜色。
- **字体角色**：中文标题与正文各自固定字体/字重，中英标点、行距和数字格式保持一致。A4新设计的正文可从10–12pt、核心图注从8.5–9.5pt试排，按实际读者和输出介质确认；这是起点，不是修改锁定模板字号的授权。重要餐宿和费用说明不能藏进极小脚注。
- **图片角色**：确定哪些位置需要真实对应照片、哪些可以用明确标注的氛围参考。图注贴近对应图框，成组照片统一留边和裁切逻辑。
- **装饰角色**：边框、图标和分隔线帮助识别内容即可。图标选同一套线条或填充风格；品牌标识用用户确认原件，不能用通用图标代替。

普通文本配色可用4.5:1作为屏幕阅读的初步对照值，参见 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。数值不代表印刷色彩验收，也不能证明图片叠字、透明度或字体可读性全部合格。

HTML构建器由四个主题色派生浅底、信息条和分隔线；浅色标题底会选择可读的标题前景色。报告中的 `palette`、`contrast_checks` 和警告供复核；用户指定的正文色不会被静默替换。该配色更新只影响重新构建的HTML，不会自动改动已有PDF或严格PPTX模板。

## 出图前决定

建立每图的 asset id、来源、确认状态、横竖比例、用途及焦点。`focus: [0.5,0.5]` 表示居中；0到1用于控制裁切方向。`fit: contain` 保留全图，允许有背景留白。不要为铺满而变形。

按实际图框估算图片像素需求，而不是只看文件大小。例如90×60mm的图框，在150ppi时约需532×355像素，在300ppi时约需1063×709像素；cover裁切后保留的区域也应足够。150/300ppi是选图估算场景，不是自动验收标准；具体印刷规格以交付要求为准。查看原图后再确认建筑、人物、菜品是否清楚。

`plan` 保存内容摘要、资产尺寸及页面结构。它是工作底稿，仍需代理补充受众、风格理由、代表页审阅结论。修改项目后必须重新plan，build会验证项目哈希。

## 密度边界

- 对照行程每页最多2天，中文上英文下，照片单独留位。更多天由代理按内容拆成连续页，工具不自动做语义分页。
- 综览页最多5个短条目，仅放摘要，不塞完整双语行程。
- 景点6图以内；指定主推2图需等宽等高；演出组和海洋馆组分别成组，不混合景点归属。
- 酒店默认每页最多3家，每家外观左、客房右、酒店名同一行，说明在图下。用户明确要求4家同页时采用紧凑布局，HTML显式设置 `compact:true`，图片默认高40mm；仍需检查建筑与客房清晰度，不再压缩到不可读。
- 餐饮2–4图，主餐与附餐优先级靠数据 `featured` 或独立页表达。车队与团队各自两图。
- 字号和分栏由实际正文长度复核。长正文退回分页，不裁掉文字或直接转换成图片。

## 独立分格、餐食与封面

独立分格HTML模板保留外框、内页纸色、标题和页脚，内页210×297mm。页面数组是明确的页序；景点、餐食、酒店、车队和行程按用户参考顺序排列，不因模板示例重新排序。每张图片有独立框和图注，不将整页参考PDF栅格图冒充新编排。

餐食展示服务行程：早餐、午晚餐、自费特色餐按原文区分。用户要求接地气时选普通桌菜、家常风味或实际自助餐场景，不加入高档摆盘与未确认菜单；图片只代表风格时写明。酒店及车辆照片同样记录来源和参考属性，不把展示图转成承诺。

用户要完整海报满版时，优先按图片比例改变首页纸张高度，后续页保持原尺寸；不能同时在不裁切、不变形的前提下把任意长海报填满A4。用户指定A4时用contain和同色背景，或取得明确的重排/裁切选择后处理。各项文字和价格不能为适配而重绘或猜写。

## 验收

看所有页的原尺寸PNG，再看整册缩略图。识别变形、主体误裁、图注错误、含文字图片与正文重复、同主题照片风格失衡。人物图需要脸部和肢体复核。检查标题和照片边缘齐线；中英段落不能错配。修改后重渲染，不以脚本成功替代目视。

代表页审阅分三次看：缩略图看整册节奏和主次；按实际阅读大小看正文、图注和费用；放大看照片质量、中文字体和裁切。手机阅读需求还应看常用屏幕宽度下的预览。记录具体页码、问题、调整及复核结果，不用无依据的“审美评分”代替判断。
