# 项目目录与交付规范

新项目默认采用下面的目录。用户指定了项目位置、团队目录或交付方式时优先使用；已有项目沿用原目录，记录各位置的对应关系，不自动搬动、重命名或复制整套资料。单页小改不必新建整套目录。

## 项目根目录

项目位置优先顺序：用户明确指定的项目文件夹 → 现有项目文件夹 → 当前工作区下新建`项目名称_宣传册`。一个项目使用独立根目录，不把客户资料放进skill安装目录或公共仓库。以下名称是新项目的默认约定，用户已有约定不需要改名。同名目录已存在时先确认是否属于当前项目；确需建立另一个项目时使用带日期或序号的不同目录名。

用户单独指定交付目录时，交付到指定位置，其他工作文件仍可在原项目目录管理。如果当前工作目录就是skill安装目录或其仓库，使用工作区中独立于该仓库的目录；确实无法判断项目位置时再问一次路径，先继续读取资料等不依赖输出位置的工作。

```text
项目名称_宣传册/
├─ 01_原始资料/
│  ├─ 01_行程与商务资料/        Word、行程、价格、航班、会议纪要
│  └─ 02_参考模板与海报/        PDF模板、参考图片、已确认KV
├─ 02_图片素材/
│  ├─ 01_景点/
│  ├─ 02_酒店/
│  ├─ 03_餐食/
│  ├─ 04_车辆/
│  ├─ 05_文化与活动/
│  ├─ 06_其他/
│  ├─ 07_处理后图片/            裁切、调色等另存副本
│  └─ 素材台账.csv
├─ 03_制作工作区/
│  ├─ 01_内容整理/              提取原文、确认记录、页码映射
│  ├─ 02_编辑源文件/            PPTX、HTML、JSON及相关资源
│  ├─ 03_预览与审阅/            样张、逐页预览、未完成审阅稿
│  ├─ 04_核对报告/              构建、渲染、页码及业务核对记录
│  └─ 05_临时文件/              中间结果，不能作为最终交付
└─ 04_交付文件/
   ├─ YYYYMMDD_v01_审阅稿/       清楚标记尚待确认
   └─ YYYYMMDD_v02_修改说明/     本轮核对后的交付文件
```

版本子目录在确有交付或审阅时创建。名称中的日期、版本和说明使用本轮实际值，例如`20261029_v02_酒店航班更新`；它们不等于客户已最终验收。已有版本继续递增、另存，不覆盖同名旧稿。

## 新项目初始化

确认项目根目录的**父目录已经存在**后，从skill目录运行。将示例中的`<工作区的绝对路径>`替换为实际工作区，不要在skill目录下创建客户项目：

```powershell
python scripts/init_project.py '<工作区的绝对路径>/项目名称_宣传册'
```

也可以把参数换成用户指定的完整新目录路径。脚本只建立上述文件夹和带表头的空白素材台账（UTF-8 BOM，便于Excel读取）；不复制、移动、删除任何输入，也不创建交付版本或生成宣传册。根目录已存在时会报错并保持原目录不变；应沿用现有项目，或选择一个新的目录名。初始化中途失败时已创建的目录或台账可能保留，查看报错并检查现场，不自动清理。

## 资料和图片如何放

- 原始资料保持原件。需要集中归档时，按用途复制到`01_原始资料`，保留原路径和文件名；原件已在合适位置时直接引用，不为满足目录树而强制复制。
- 图片按主体放入`02_图片素材`相应目录；已有图片原件在其他合适位置时可直接引用并登记，不强制迁移。同一家酒店的外观、房型用清晰名称配对，例如`酒店名称_外观.jpg`、`酒店名称_双床房.png`。原文件重名时另起名称，不能覆盖。裁切或处理后另存到`07_处理后图片`，保留原图。
- `素材台账.csv`的空白表头只用于记录，不代表素材已核实。每张实际使用的图填入类别、主体、原始/项目内路径、来源类型、原图网址、作者、许可与使用范围、使用位置、裁切焦点、确认状态、SHA256等已知信息；不确定的项标明待核实，不编造。来源类型可写用户提供、官方、图库或AI示意等。查找与授权细节见[素材库流程](asset-libraries.md)。
- AI示意、通用氛围图和真实对应照片在台账及需要的图注中区分；图中菜品不自动变成固定菜单，通用酒店图不冒充入住酒店。需要保留外链、字体或外部图片才能编辑时，要记录依赖及实际位置。

## 工作区与交付区如何分开

工作区保存制作约定、原文提取、设计源文件、样张及自动/人工核对记录；不要把未完成的预览当成成品。新一轮修改先按[多轮修改流程](revision-review.md)确定上次实际交付的PDF、对应源文件和需要修改的页。

新项目可将简短的`制作约定.md`放在`01_内容整理`，记录来源角色、已确认口径、待确认事项和最新文件对。`04_核对报告`按实际执行的检查保存，例如`YYYYMMDD_vNN_渲染检查.json`、`YYYYMMDD_vNN_改动核对.json`、`YYYYMMDD_vNN_人工复核.md`；未做过的检查不生成“通过”记录。逐页预览与审阅样张放在`03_预览与审阅`。

默认每次实际交付或发审阅稿时，在`04_交付文件`建立独立版本目录，放入用户要求的PDF、可编辑源文件及必要的说明/配套资源。用户要求直接保存到指定文件夹时按该要求执行，并用不同文件名保留旧稿。文件名采用`项目名称_YYYYMMDD_vNN_用途.扩展名`，同一版PDF和源文件使用相同日期、版本号；已有客户命名规则优先。未完成稿在目录和文件名中明确写`审阅稿`或`待核对`。

版本目录需要说明时，可放`交付说明.txt`，列出文件用途、日期与版本、已核对事项、尚待确认事项，以及可编辑源文件所需的配套资源；说明应与该目录中的实际文件相符。

交付前重新打开**交付目录中的文件**，确认PDF与源文件对应、文件可用、依赖齐全、页数与检查结果符合本轮要求。报告或素材源包是否交付按用户需求及具体使用许可处理；不要因源文件引用而把不允许再分发的图库、字体或客户资料上传到公共仓库。交付消息给出当前版本的具体文件链接，说明改动、已核对项和仍待确认事项。
